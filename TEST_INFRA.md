# Flame Chess E2E Test Infrastructure & Screenshot Harness

## Overview
This document describes the Playwright end-to-end (E2E) testing framework and automated screenshot verification harness established for the Flame Chess UI redesign.

The test infrastructure validates core frontend views, authentication flows, theme switching (Light and Dark mode variants), chessboard interactions, API endpoints, and modal dialogs.

---

## 📁 Layout & Structure

All E2E test files, configuration, servers, and screenshot outputs are housed under `e2e/`:

```
e2e/
├── package.json               # Node.js dependencies & test script runners
├── playwright.config.js       # Playwright runner configuration & webServer integration
├── dev-server.js              # Embedded Node.js HTTP/REST API & WS mock dev server
```

## 🎯 Test Categories (Tiers 1–4)

The test suite is structured into four progressive tiers:

### 1. Tier 1: Authentication & Theme Infrastructure (`tier1_auth_theme.spec.js`)
- **Server Health Check**: Verifies `GET /healthz` returns `{ "status": "ok" }`.
- **Landing View**: Validates login screen rendering (`#view-landing`).
- **Dev Login**: Tests `/auth/dev-login` cookie-based session authorization (`fc_session`).
- **Theme Switcher**: Tests switching between Light (`data-theme="light"`) and Dark (`data-theme="dark"`) modes via `#themeToggleBtn` or `applyTheme()`.
- **Logout Flow**: Tests `POST /auth/logout` session invalidation.

### 2. Tier 2: Dashboard & Navigation (`tier2_dashboard_nav.spec.js`)
- **Lobby View**: Validates dashboard rendering (`#view-lobby`) and top bar (`#topbar`).
- **Profile Display**: Checks display name (`#barName`), online user count (`#onlinePill`), and rating badge.
- **Leaderboard**: Tests leaderboard data fetching (`GET /api/leaderboard`) and rendering (`#leaderboardTable`).
- **Game History**: Verifies past game queries (`GET /api/games`) and history panel.
- **Challenge Creation**: Tests challenge link generation (`POST /api/challenges`).

### 3. Tier 3: Gameplay & Chessboard (`tier3_gameplay_clocks.spec.js`)
- **Gameplay View**: Validates interactive chess view container (`#view-game`).
- **Chessboard Render**: Verifies 8x8 grid rendering (`#board`), square coordinates (`a1`–`h8`), and SVG piece symbols.
- **Clock Timers & Turn State**: Validates countdown clocks (`#whiteClock`, `#blackClock`) and turn indicators.
- **In-Game Controls**: Verifies Resign (`#resignBtn`) and Offer Draw (`#drawBtn`) button functionality.

### 4. Tier 4: Game Over & Modals (`tier4_gameover_modals.spec.js`)
- **Game Over Modal**: Validates victory/defeat dialog (`#overlayRoot`), score changes, and result text ("White Wins by Checkmate").
- **Rematch Flow**: Tests rematch request controls (`#rematchBtn`).
- **Live Spectating**: Verifies live game listing (`GET /api/games/live`) and spectator controls (`#stopWatchBtn`).
- **Profile & Settings Modals**: Validates display name editing and profile dropdown popup (`#profileDropdown`).

## 🚀 Runner Commands

Navigate to the `e2e/` directory before running commands:

```bash
cd e2e
```

| Command | Description |
|---------|-------------|
| `npm test` | Runs the full Playwright E2E test suite (Tiers 1–4) in headless mode. |
| `npm run test:ui` | Opens Playwright Interactive UI mode for step-by-step test debugging. |
| `npm run capture-screenshots` | Executes the screenshot harness to capture high-res Light & Dark screenshots. |
| `npm run start-dev-server` | Launches the local dev server on `http://localhost:8080`. |
| `npx playwright show-report` | Opens HTML test execution report. |

## ⚙️ Server Configuration & Auto-Launch

The Playwright test runner and screenshot harness automatically manage local server lifecycle:
- If a server is already active on `http://localhost:8080`, Playwright connects to it (`reuseExistingServer: true`).
- If no server is running, Playwright automatically spawns `node dev-server.js` on port `8080`.
